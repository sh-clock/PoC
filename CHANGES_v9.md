Base: PoC v8 (100% line-by-line audited, all 21 modes verbatim, byte-exact
GTE jitter, zero v7 regressions). v9 adds the two v9-task deliverables and

## 1. ALL 21 MODES SELECTABLE INTERACTIVELY (the v9 headline feature)

- **Tab** — on-screen WORLD MODE BROWSER (X11/SDL2/Win32): 21 preset rows
  + 24 authentic-pair rows with live fog/spot/wLI/maxB/enum columns,
  Up/Down + Enter to apply, 0-9 to jump+apply, Esc closes. `--menu`
  boots with it open.
- **[ / ]** — cycle all 21 presets (Gfx_MapEnvSet(k,k) — engine-legal
  identical pairs like {16,16}, {13,13}).
- **, / .** — cycle the 24 authentic pairs (map-defaults D_800A9F80..A4 +
  every map event call site + the load-screen blend targets).
- **H** — toggle the live status HUD (current pair, fog mode/distance/
  color, wLI, spot, flashlight fade).
- **--preset N** — boot at preset N; **--no-hud** — hide the HUD.
- New 8x8 embedded font `src/sh_font8.h` (generated by
  `tools/gen_font8.py` from DejaVu Sans Mono) — debug-UI chrome ONLY.
- Every selection routes through the UNTOUCHED verbatim
  `sh_env_set_pair` == `Gfx_MapEnvSet` port. The overlay is drawn after
  `render_frame()` in the window loops ONLY — the deterministic
  `--shot`/`--benchmark` paths never call it, so every golden render
  stays byte-identical (re-proven by the v8-binary A/B below).
- No input lag: key handling is the same one-event-per-frame dispatch;
  no new polling, no sleeps. v8 keys (N/F/M/B/P/W/L/S/R/SPACE/±/arrows)
  unchanged; F still refuses when the engine gate says no
  (isFlashlightUnavailable / FlashlightAllowed).

## 3. DECOMP-FIDELITY CORRECTION OF THE v8 PRESET TABLE (LOUD)

Found by re-reading map_info.c raw during the v9 documentation pass:

1. **CHUNK_SIZE mis-read (12 entries).** v8 encoded fogDistance 32768
   (= Q12(8.0)) for presets 3,4,8,9,10,11,12,14,15,16,18,20 whose decomp
   value is `Q12(CHUNK_SIZE)`. `include/bodyprog/map/terrain.h:7`:
   `#define CHUNK_SIZE 40.0f` (cross-confirmed by 15+ Q8(CHUNK_SIZE)
   chunk-grid uses in world_map.c). Correct value: **163840 = 40 m**.
   Steady-state renders of those presets are unchanged (field_E=0 =>
   fog already OFF); the flashlight FADE now sweeps 14 m -> 40 m
   (engine-exact) instead of 14 m -> 8 m, and lightning preset 8's fog
   is 40 m. verify.sh's preset-8 assertion and tools/env_audit.py's
   blend_tick reference updated to the decomp values (the audit tool
   also had a broken mismatch-print that only fired on mismatch —
   v8's wrong constants never triggered it).
2. **Entries 16-20 were rotated one slot.** v8: [16..20] = THICK,
   spotlight, blue-night, s06, dim. Decomp raw order (map_info.c
   262-341): **[16]=dim(1.4) [17]=THICK(6.5 m) [18]=spotlight(2.5)
   [19]=blue-night(15 m) [20]=s06(0.8)** — proven by the call-site
   literals {16,16}@map3_s02_2.c:267+map6_s01_2.c:190,
   {18,18}@map7_s03_3.c:953, {17,17}@map7_s03_3.c:3083/3185/3395,
   {19,4}@map1_s06.c:68, {6,20}@map4_s03.c:1830.

### Regression proofs (all re-run after the correction)

- verify.sh FULL suite: ALL PASS (determinism, bridges, turn filter,
  camera audit 30x401, env audit 539 samples 0 mismatches, env BLEND
  audit 181 ticks 0 mismatches, 21 self-pair renders, rain, weather
  fade, lensflare, dynamic fog, lightning one-tick, window env ticks).
- PRISTINE v8 BINARY A/B (25 render cases): **16/25 BYTE-IDENTICAL**
  (day, night no-FL, night FL, nightmare no-FL, nightmare FL,
  {6,5} dynamic fog, {6,6}, {2,2}, {11,11}, {9,9}, {6,10}, {6,12},
  {19,4}, rain, modern, turn) — **9/25 differ EXACTLY as the decomp
  predicts** (the rotated indices' content swaps + {8,8} fog 8->40 m).
  The v8-approved look is preserved everywhere the v8 data was already
  correct; the 9 changed renders ARE the corrections.
